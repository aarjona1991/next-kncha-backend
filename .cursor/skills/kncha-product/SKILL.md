# KNCHA Product Rules

## What KNCHA is

Backend + API + admin (+ mini `/play` client) to **complete football rosters**
when friends drop out. Not a generic events app.

## Scope (MVP)

- Sports: **futbol5** (10) and **futbol7** (14) only
- Geography: Uruguay (zones = city/barrio catalog)
- Users: **18+ only** — no school/institutional mode in MVP
- Avatars: `photoUrl` string (Hostinger/CDN), not Firebase Storage

## Core flows

1. Organizer creates **private** event
2. Invite friends via **link** → direct roster join (no poll)
3. If still short, **publish** to public feed
4. Strangers **request join** → group **poll** in event chat
5. **3h before start**: poll closes → organizer decides (or postpones)
6. After match: **keep-group** majority vote

## Hard rules (enforce server-side)

| Rule | Value |
|------|-------|
| Min age | 18 (`birthDate` YYYY-MM-DD) |
| Audience | `mixed` \| `men` \| `women` — validate on every join |
| F5 capacity | 10 |
| F7 capacity | 14 |
| Max active events / organizer | 2 |
| Default visibility | `private` |
| Publish requires | sport + zoneId + approxDate + audience |
| Rookie score | 1000, badge `rookie` (autogenerated, not self-reported) |
| Poll close | 3h before `startsAt`, or end of `approxDate` if no time |

## Join paths

| Entry | Behavior |
|-------|----------|
| Invite link / code | Direct to roster + chat |
| Public feed | Join request → poll → organizer accept/reject |

## Roster mutations

- Join = "voy"; user can **leave**
- **Only organizer** can **kick**
- Leave/kick → **system chat message** + notify organizer if hole opens
- Organizer chooses: reopen public or complete via links only

## Vocabulary (use consistently)

- **Nómina** = roster
- **Organizador** = event creator (also a player)
- **Poll** = group vote on join requests (not event creation poll)
- **Tarjeta deportiva** = public profile card (future consumer UI)

## Out of scope (do not implement unless asked)

- Team balancer, rich feedback/badges, GPS, monetization
- School events, Firebase Storage avatars, FCM push (MVP uses Firestore notifications docs)
- Full consumer app with kncha.online branding (only `/play` mini client here)

## When changing product behavior

1. Update domain logic in `src/lib/domain/*`
2. Update Zod validators if input shape changes
3. Add/adjust tests in `tests/unit/` or `tests/api/`
4. Update README if API surface changes
